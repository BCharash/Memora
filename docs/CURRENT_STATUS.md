## Manual eligibility clarification and proposed simplification

Current code separates a passing attempt from eligibility restoration: only a qualifying pass with deliberateRetest:true clears an existing exact-context or legacy hold. The .15 adaptive button records that flag when the selected context is suspended/failed; users do not manage it. Do not conclude that every report with false stayed ineligible. Ordinary transcription failures are not yet persisted as eligibility evidence; only self-test/recovery outcomes drive the gate.

Approved manual rule (implemented in .17 above): any completed qualifying **manual** test of the exact configuration/context restores its eligibility, retaining earlier adverse evidence and legacy-review resolution identity. Run test/Retest wording can describe prior state without controlling permission to recover. This change is separate from resource diagnostics; see .17 verification above. Manual tests remain unlimited. Automatic sequences, when resumed later, have one initial attempt plus one automatic retry and their own qualification policy; do not silently apply manual recovery to automatic retries.
