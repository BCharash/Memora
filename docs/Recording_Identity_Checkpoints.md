## Identity decisions

1. **Recording ID identifies audio.** Reuse a valid embedded ID. Transcript headers reference that ID; matching audio verifies the association. Filename and folder names locate candidates but are not identity authorities. Archive UUID continues to identify the transcript archive.
2. **Rare unidentified audio uses a reproducible sampled fingerprint.** Derive it from file size in bytes and SHA-256 of the first **250 KiB (256,000 bytes)**, or the whole file when smaller. Exclude filename, path, dates, device and Audio Source ID. Freeze method/version, encoding and stored representation at checkpoint 1 before writing new IDs. Current validators assume UUIDs, so a new representation requires deliberate compatibility work; do not simply insert an arbitrary digest into UUID fields.
3. **Sampling is a practical compromise.** Renaming preserves the fingerprint; changes outside the prefix may not affect it. Different files with the same size and sampled bytes cannot be distinguished by this method. Duplicate/ambiguous candidates must be presented with their locations rather than silently resolved. Do not claim a full-content checksum. File.size supplies the size without application content reads, but Files/iCloud may download a whole remote file to supply a slice; partial application reads do not guarantee partial network transfer.
4. **Audio JSON is a rebuildable inventory.** Keep memora-audio-source.json, preserving known IDs/unknown accepted fields in normal reconciliation, updating membership only when justified and avoiding unchanged saves. A missing list can be recreated from audio using the same identity rules. An internal catalogue ID may remain for bookkeeping, but it must not control transcript/audio matching. Rebuilding should not require TXT repairs or embedding regeneration.
5. **Retire transcript Audio Source ID.** Stop writing it in new headers. Accept historical headers with or without it and ignore that field for audio association. Apply this consistently to parsing/validation, playback, persistence, reconciliation, recovery, cache scoping and tests. Removing just the header line would leave other dependencies intact. Different source UUIDs alone must not reject matching recordings; conflicting Recording IDs still must.
6. **Each transcript subfolder remains independent.** Select the parent audio archive, discover immediate transcript subfolders and open one chosen folder. Each retains its own memora-transcript-archive.json and search-embeddings.json. Preserve direct transcript-folder selection. Desktop uses native directory handles where supported; iPhone retains directory-input access and explicit Files saves with archive/subfolder guidance. Broader multi-archive Combine workspace work remains separate; its future references should use recording identity plus available locations rather than depend on one permanent audio-list UUID.
7. **Retire identity-recovery copies after compatibility is proven.** Remove the accumulated Audio Recording List saved-copy cache and its Settings section. Preserve pending unsaved list/transcript exports and remembered desktop folder access as separate functions. Legacy randomly assigned Recording IDs must not be discarded while transcripts depend on them: retain/map or export those associations before cache retirement. The user reports all current archive audio has embedded IDs, so this exception should not affect their normal path; support for other users still needs checking.
