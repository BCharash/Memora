# Memora Paragraphing: Revision 4 vs Revision 5 — Complete Decision and Technical Record

**Prepared:** 17 October 2026  
**Purpose:** Self-contained record for future reconsideration of Revision 4 (R4) versus Revision 5 (R5). This document records the source implementation, the evaluation dataset, the measurable output differences, the editorial boundary reviews, the decision rationale, caveats, and a safe path for revisiting the choice. It is intended to be usable without relying on the prior conversation.

---

## 1. Executive conclusion

**Current decision: Revision 4 is the leading candidate and is provisionally preferred over Revision 5.** This is a practical editorial decision based on the available full-archive comparison and a manual review of the boundaries on which the two versions disagree. It is not a claim that R4 is perfect or that it has been proven superior at every boundary.

The deciding observation was not simply that R4 creates more paragraphs. It was the character of the *unique* boundaries:

- Of **110 boundaries present in R4 but absent from R5**, the review judged **67 useful or defensible (61%)**, **40 unnecessary/fragmenting (36%)**, and **3 borderline (3%)**.
- Of **45 boundaries present in R5 but absent from R4**, the review judged **18 useful or defensible (40%)**, **21 unnecessary/fragmenting (47%)**, and **6 borderline (13%)**.

These are subjective editorial classifications, not ground-truth labels or a formal statistical test. The pattern nevertheless favours R4: the boundaries it uniquely adds were more often judged helpful, whereas R5's unique boundaries were not more often helpful than fragmenting. R5's persistence requirement appears to remove some useful breaks as well as some poor ones.

**Do not begin another broad algorithm-design cycle by default.** Keep R4 as the preferred candidate, preserve R5 for comparison, and revisit only if a specific defect is identified or new representative evidence materially changes the balance. The decision can be revisited later using this record and the source files named below.

No production integration is implied by this decision. The paragraphing lab is an experimental evaluation tool; production code must be reviewed and updated separately using the current production files.

### What the review was trying to optimize

The user's stated editorial priorities were:

- Use semantic context rather than hard-coded transition-word/discourse-marker lists.
- Do not rewrite transcript wording, punctuation, or metadata; only paragraph boundaries should change.
- Do not force a split solely because a paragraph is long.
- Prefer readable paragraphing, but avoid breaking an explanation away from its example, premise from its consequence, or a continuous narrative mid-event.
- Accept that paragraphing is a judgment task: the aim is a useful, consistent result, not perfect boundaries in every transcript.
- Avoid an open-ended series of algorithm revisions without evidence of a repeatable improvement.

## 3. Shared technical basis

Both R4 and R5 use sentence embeddings generated by the lab's shared code:

- Transformers.js **3.7.2**, imported from jsDelivr.
- Model: **`Xenova/all-MiniLM-L6-v2`**, configured with `dtype: 'q8'`.
- Each sentence is embedded separately with mean pooling and normalized output.
- Boundary scoring compares averages of sentence-embedding vectors on either side of a possible break, plus the embedding discontinuity between the two adjacent sentences.
- The model is loaded in the browser. The lab notes that first-run model/runtime downloads require internet access; transcript text stays in the browser and is not uploaded by the lab code.
- The algorithms use the same sentence-splitting and word-counting helpers, the same embedding pipeline, and the same `applyBreaks` function.

The relevant shared helper code is included in Section 8. The full lab also contains the UI, ZIP reading, comparison rendering, reporting, and earlier experimental algorithms; those do not define the R4/R5 scoring distinction.

### Important shared limitations

1. **Sentence splitting is heuristic.** It protects a small set of abbreviations (`Mr.`, `Mrs.`, `Dr.`, `Ms.`, `e.g.`, `i.e.`), then splits on sentence-ending punctuation. Other abbreviations, transcription punctuation, or unusual spoken syntax may affect sentence boundaries.
2. **Embedding similarity is evidence, not understanding.** It measures semantic representation shifts and cannot reliably distinguish every new topic from a sentence that introduces, explains, qualifies, or concludes the same topic.
3. **Existing paragraph handling matters.** Both R4 and R5 preserve existing paragraphs at or below 120 words. Longer paragraphs are candidates for re-analysis; this is not a complete re-paragraphization of every short paragraph.
4. **No forced long-paragraph split.** A paragraph can remain very long if no candidate satisfies the algorithm's criteria. This is deliberate, not a bug by itself.
5. **Reproducibility depends on the exact runtime/model.** The model revision, Transformers.js version, sentence splitting, and vector behavior should be held constant when reproducing the comparison.

## 5. Revision 4: design and exact decision logic

### Intended behavior

R4 is described in the lab as **“semantic-only boundary evidence plus a soft readability preference.”** It deliberately does not inspect transition words, discourse markers, or phrase lists. Length never forces a split; it only modestly increases the priority of an already semantically plausible candidate.

### R4 configuration

```js
const REV4_CONFIG={reprocessAboveWords:120,minSegmentWords:42,minSegmentSentences:2,shortWindow:2,longWindow:4,minimumScore:0.058,quantile:0.62,localRadius:1,minBoundaryGapSentences:2,softReviewWords:165,pressureCap:0.035};
```

| Parameter | Value | Meaning |
|---|---:|---|
| `reprocessAboveWords` | 120 | Preserve existing paragraphs of 120 words or fewer; consider longer paragraphs for re-analysis. |
| `minSegmentWords` | 42 | Each resulting segment must have at least 42 words. |
| `minSegmentSentences` | 2 | Each resulting segment must have at least 2 sentences. |
| `shortWindow` | 2 | Average up to 2 sentence embeddings on each side for short-range shift. |
| `longWindow` | 4 | Average up to 4 sentence embeddings on each side for broader context. |
| `minimumScore` | 0.058 | Absolute floor for a candidate semantic-shift score. |
| `quantile` | 0.62 | Adaptive score threshold uses the 62nd percentile of candidate scores, subject to the absolute floor. |
| `localRadius` | 1 | Compare a candidate to adjacent boundary scores to favor local peaks. |
| `minBoundaryGapSentences` | 2 | Do not place chosen boundaries too close together. |
| `softReviewWords` | 165 | Word-count point after which soft priority begins to rise. |
| `pressureCap` | 0.035 | Maximum additive length-related ranking pressure. |

### R4 score

For a candidate boundary after sentence `i`:

- `shortShift = 1 - cosine(mean(left 2 sentence embeddings), mean(right 2 sentence embeddings))`
- `longShift = 1 - cosine(mean(left 4 sentence embeddings), mean(right 4 sentence embeddings))`
- `localGap = 1 - cosine(embedding(sentence i-1), embedding(sentence i))`

The semantic score is:

`semanticShift = 0.55 × shortShift + 0.30 × longShift + 0.15 × localGap`

This combines immediate local change, broader topic-context change, and the discontinuity between adjacent sentences. Short-range context has the greatest weight.

### R4 candidate selection

1. Compute an adaptive score threshold: the greater of `0.058` and the 62nd percentile of the candidate scores.
2. Discard candidates below the threshold.
3. Keep candidates that are local peaks within a radius of one boundary, allowing a tolerance of `0.012`.
4. Add a small length-related **ranking** pressure based on words before the boundary once the running segment exceeds 165 words. The pressure is capped at `0.035`. It changes candidate priority, not eligibility by itself.
5. Consider higher-ranked candidates first, but reject a boundary if either resulting segment would have fewer than 2 sentences or fewer than 42 words, or if it would be too close to a previously chosen boundary.
6. Return chosen boundaries in sentence order.

### R4 paragraph processing

For each existing paragraph:

1. If it has 120 words or fewer, preserve it as-is.
2. Otherwise split into sentences.
3. If there are fewer than twice the minimum segment sentence count (fewer than 4 sentences), preserve it.
4. Embed the sentences, score all possible boundaries, choose boundaries, and join the resulting sentence groups with paragraph breaks.
5. If no candidate passes the criteria, preserve it as one paragraph. Long length alone does not force a split.

## 6. Revision 5: design and exact decision logic

### Intended behavior

R5 is described in the lab as **“persistence-aware semantic boundaries.”** It tries to avoid splitting between an idea and its example or explanation by requiring a candidate semantic shift to remain distinguishable when the sentences after the boundary are compared with the preceding topic.

This is a reasonable hypothesis: a true topic shift may persist into subsequent sentences, whereas a sentence that elaborates an existing point may quickly return to the previous semantic context. The manual review, however, suggests the persistence test is too restrictive or not sufficiently aligned with the human concept of a useful paragraph boundary.

### R5 configuration

```js
const REV5_CONFIG={reprocessAboveWords:120,minSegmentWords:48,minSegmentSentences:2,shortWindow:2,longWindow:4,persistenceWindow:3,minimumScore:0.065,quantile:0.66,localRadius:2,minBoundaryGapSentences:3,softReviewWords:190,pressureCap:0.018};
```

| Parameter | Value | Difference from R4 |
|---|---:|---|
| `reprocessAboveWords` | 120 | Same |
| `minSegmentWords` | 48 | Higher than R4's 42 |
| `minSegmentSentences` | 2 | Same |
| `shortWindow` | 2 | Same |
| `longWindow` | 4 | Same |
| `persistenceWindow` | 3 | New: examine subsequent sentences to estimate whether the new topic persists. |
| `minimumScore` | 0.065 | Higher than R4's 0.058 |
| `quantile` | 0.66 | Higher than R4's 0.62 |
| `localRadius` | 2 | Wider than R4's radius of 1 |
| `minBoundaryGapSentences` | 3 | Wider spacing than R4's 2 |
| `softReviewWords` | 190 | Later than R4's 165 |
| `pressureCap` | 0.018 | Lower than R4's 0.035 |

### R5 score

R5 calculates the same three semantic signals as R4 and adds a persistence term:

- `rightShort` is the mean of up to two embeddings after the boundary.
- `later` is the mean of up to three embeddings beginning one sentence after the first post-boundary sentence.
- `persistence = max(0, cosine(rightShort, later) - cosine(leftShort, later))`

The score is:

`semanticShift = 0.42 × shortShift + 0.28 × longShift + 0.12 × localGap + 0.18 × persistence`

Compared with R4, R5 lowers the weight of all three original signals and assigns 18% to persistence.

### R5 candidate selection

1. Compute an adaptive threshold: the greater of `0.065` and the 66th percentile of the semantic score distribution.
2. Reject candidates below the threshold **or** with `persistence < 0.015`.
3. Keep local peaks within a radius of two boundaries, allowing a tolerance of `0.008`.
4. Add a weaker soft length-ranking pressure beginning after 190 words, capped at `0.018`.
5. Enforce at least 2 sentences and 48 words on either side, plus a minimum gap of 3 sentences between chosen boundaries.
6. Return the selected boundaries in order.

### What changed conceptually

R5 is not simply R4 with a different threshold. It changes the hypothesis used to select boundaries:

- R4 asks: **Is there a sufficiently strong semantic shift at this boundary, considering both short and broader context?**
- R5 asks: **Is there a sufficiently strong semantic shift, and does the post-boundary context remain more aligned with the new local context than with the previous one?**

The persistence condition can be useful for avoiding some false positives, but it also risks rejecting valid paragraph breaks where the next few sentences return to the earlier idea to explain, qualify, or finish it. Human paragraphs often mark a shift in rhetorical function—not just a sustained shift in embedding similarity. A paragraph can appropriately begin with an example or explanation that is semantically close to the preceding idea.

#### Boundary scoring

```js
function revision4BoundaryScores(S,E){const offsets=sentenceOffsets(S),out=[];for(let i=1;i<S.length;i++){const leftShort=meanRange(E,i-REV4_CONFIG.shortWindow,i),rightShort=meanRange(E,i,i+REV4_CONFIG.shortWindow),leftLong=meanRange(E,i-REV4_CONFIG.longWindow,i),rightLong=meanRange(E,i,i+REV4_CONFIG.longWindow);if(!leftShort||!rightShort||!leftLong||!rightLong)continue;const shortShift=1-cosine(leftShort,rightShort),longShift=1-cosine(leftLong,rightLong),localGap=1-cosine(E[i-1],E[i]);const semanticShift=shortShift*.55+longShift*.30+localGap*.15;const wordsBefore=offsets[i],wordsAfter=offsets[S.length]-offsets[i];out.push({i,semanticShift,shortShift,longShift,localGap,wordsBefore,wordsAfter,before:clipText(S[i-1],220),after:clipText(S[i],220)});}return out}
```

#### Boundary selection

```js
function chooseRevision4Breaks(S,scores){if(!scores.length)return [];const shifts=scores.map(x=>x.semanticShift).sort((a,b)=>a-b),adaptive=Math.max(REV4_CONFIG.minimumScore,quantile(shifts,REV4_CONFIG.quantile));const candidates=scores.map((b,k)=>{const pressure=Math.min(REV4_CONFIG.pressureCap,Math.max(0,b.wordsBefore-REV4_CONFIG.softReviewWords)*0.00012);return {...b,pressure,rankScore:b.semanticShift+pressure,k}}).filter(b=>{if(b.semanticShift<adaptive)return false;const near=scores.slice(Math.max(0,b.k-REV4_CONFIG.localRadius),b.k).concat(scores.slice(b.k+1,Math.min(scores.length,b.k+1+REV4_CONFIG.localRadius)));return near.every(x=>b.semanticShift>=x.semanticShift-0.012)}).sort((a,b)=>b.rankScore-a.rankScore);const chosen=[];for(const b of candidates){const i=b.i,prior=chosen.filter(x=>x<i).sort((a,b)=>b-a)[0]||0,next=chosen.filter(x=>x>i).sort((a,b)=>a-b)[0]||S.length;const beforeWords=sentenceOffsets(S)[i]-(prior?sentenceOffsets(S)[prior]:0),afterWords=(sentenceOffsets(S)[next]-sentenceOffsets(S)[i]);if(i-prior<REV4_CONFIG.minSegmentSentences||next-i<REV4_CONFIG.minSegmentSentences)continue;if(beforeWords<REV4_CONFIG.minSegmentWords||afterWords<REV4_CONFIG.minSegmentWords)continue;if(chosen.some(x=>Math.abs(x-i)<REV4_CONFIG.minBoundaryGapSentences))continue;chosen.push(i)}return chosen.sort((a,b)=>a-b)}
```

### 7.3 Shared helper code

These helpers materially affect the behavior of both algorithms. The snippets are copied from the same lab source.

#### Sentence splitting

```js
function sentenceSplit(text){text=text.replace(/\n+/g,' ').replace(/\s+/g,' ').trim().replace(/\bMr\./g,'Mr§').replace(/\bMrs\./g,'Mrs§').replace(/\bDr\./g,'Dr§').replace(/\bMs\./g,'Ms§').replace(/\be\.g\./gi,'eg§').replace(/\bi\.e\./gi,'ie§');const out=text.match(/[^.!?]+(?:[.!?]+["'’”)]*)?(?=\s+|$)/g)||[text];return out.map(s=>s.replace(/§/g,'.').trim()).filter(Boolean)}
```

#### Word counting

```js
function words(s){return (s.match(/[\p{L}\p{N}’'-]+/gu)||[]).length}
```

#### Existing paragraph splitting

```js
function existingParas(text){return text.split(/\n\s*\n/).map(x=>x.trim()).filter(Boolean)}
```

#### Cosine similarity

```js
function cosine(a,b){let d=0,aa=0,bb=0;for(let i=0;i<a.length;i++){d+=a[i]*b[i];aa+=a[i]*a[i];bb+=b[i]*b[i]}return d/(Math.sqrt(aa)*Math.sqrt(bb)||1)}
```

#### Mean vector

```js
function mean(E,a,b){if(b<=a)return null;const n=E[0].length,r=new Array(n).fill(0);for(let i=a;i<b;i++)for(let j=0;j<n;j++)r[j]+=E[i][j]/(b-a);return r}
```

#### Quantile

```js
function quantile(a,p){if(!a.length)return 0;return a[Math.floor((a.length-1)*p)]}
```

#### Mean range

```js
function meanRange(E,a,b){return mean(E,Math.max(0,a),Math.min(E.length,b))}
```

#### Sentence offsets

```js
function sentenceOffsets(S){const starts=[];let n=0;for(const s of S){starts.push(n);n+=words(s)}starts.push(n);return starts}
```

#### Applying selected breaks

```js
function applyBreaks(S,breaks){const out=[];let s=0;for(const b of [...breaks,S.length]){if(b>s)out.push(S.slice(s,b).join(' '));s=b}return out}
```

## 8. Manual review of disagreements

### Method

The editorial comparison focused on the full paragraphs on either side of the boundaries unique to each version. The guiding question was whether the new paragraph starts a useful unit of thought or whether the break separates a continuous explanation, example, consequence, qualification, or narrative.

The review categories were:

- **Useful / defensible:** a natural or reasonable separation of a new example, subtopic, narrative phase, application, or reflective move.
- **Unnecessary / fragmenting:** splits one continuous thought, separates a statement from its immediate explanation/consequence, or interrupts a narrative without a useful change in function.
- **Borderline:** defensible either way or dependent on editorial preference.

These categories were applied by a human editorial pass and are not model-generated confidence labels. “Useful / defensible” does not necessarily mean the break is essential. A break can be reasonable without being mandatory.

## 9. Why R4 was selected over R5

The choice rests on four pieces of evidence, considered together.

### 9.1 R4 better matches the desired paragraph density

R4 produces 485 paragraphs, compared with 420 for R5, and a median paragraph length of 83 words rather than 96. The user explicitly preferred readable paragraphing with enough paragraph breaks, provided the breaks do not fragment connected ideas. R4's somewhat denser paragraphing is consistent with that preference.

This is not sufficient by itself: more paragraphs can also mean more fragmentation. The qualitative review is the reason this metric matters only as supporting evidence.

### 9.2 R4's unique boundaries were more often judged useful

R4 has 110 unique boundaries and R5 has 45. The editorial review judged 67/110 R4-only boundaries useful or defensible, compared with 18/45 R5-only boundaries. R4's unique boundaries therefore offer more potential benefit, while the R5-only set is slightly more likely to be judged fragmenting than helpful.

### 9.3 R5's persistence test appears too restrictive for the task

The R5 design assumes that a valid topic shift should persist in the next few sentence embeddings. But paragraph boundaries often reflect rhetorical function:

- introducing an example of the same topic;
- moving from a general principle to a personal application;
- beginning a story whose meaning is connected to the preceding reflection;
- separating a new subtopic even when its vocabulary remains semantically close;
- pausing after a completed idea before continuing a related idea.

Those shifts may not be detected as persistent embedding changes. Conversely, the persistence metric can still pass a boundary that divides one continuous thought. The manual review did not show that the added persistence test reliably distinguishes the human editorial cases that matter.

### 9.4 The output metrics do not justify R5's lost boundaries

R5 has slightly more paragraphs over 180/250/300 words and the same longest paragraph as R4. Thus, in this output, the persistence test does not produce a meaningful advantage in the long-paragraph tail. It produces fewer paragraphs overall, but the review suggests that some of the removed boundaries were useful.

### Decision statement

**R4 is selected provisionally because it better balances readability and semantic continuity in the evidence available.** R5 remains a comparison candidate and is not discarded as useless. The decision is reversible if a later, controlled review provides contrary evidence.

## 10. What this comparison does and does not prove

### Supported conclusions

- The two implementations differ in identifiable ways described in Sections 5–7.
- On the latest 93-transcript comparison, R4 produces 485 paragraphs and R5 420.
- They share 282 proposed boundaries; R4 uniquely adds 110 and R5 uniquely adds 45.
- The editorial review judged R4's unique boundaries more favorably than R5's unique boundaries.
- This supports choosing R4 as the current leading candidate.

### Not established

- That R4 is objectively correct at 61% of all its boundaries. The 61% figure applies only to the R4-only boundary set and includes “defensible,” not just essential, breaks.
- That R4 is superior at the 282 shared boundaries. Those shared boundaries were not independently rescored in this disagreement analysis.
- That every transcript or every type of speech will behave like this 93-transcript corpus.
- That a future runtime/model version will reproduce the exact same output.
- That the R4 algorithm is already integrated into Memora production. It is not established by these artifacts.
- That the longest paragraph is automatically a failure. A long paragraph may be coherent, although the 531-word maximum is worth inspecting if it becomes a real usability issue.

### Editorial uncertainty

The reviews are judgment calls. Some boundaries marked “useful/defensible” are optional rather than necessary. A different editor might classify some cases differently. The right response to that uncertainty is to preserve the examples and rationale—not to pretend the counts are a ground-truth benchmark.

## 11. Revisit protocol: when and how to reconsider the decision

Do not revisit R4 versus R5 merely because the paragraphing is imperfect. Revisit if one of these occurs:

1. A specific, repeatable error appears in several transcripts.
2. A real-world use of R4 reveals a class of undesirable splits that materially affects reading.
3. A new evaluation set shows a consistent advantage for R5 or another method.
4. The embedding model/runtime changes, invalidating the current comparison.
5. The user explicitly wants a new review.

If revisiting:

1. Use the exact source functions in Section 7 and the same 93-transcript JSON as the historical baseline.
2. Identify the concrete defect before changing any parameter.
3. Inspect full paragraphs on both sides of the disputed boundary—not only adjacent sentences or a semantic score.
4. Classify the change as a helpful split, fragmenting split, or borderline.
5. Record the transcript name and boundary location, plus the before/after text.
6. Require multiple examples of the same failure pattern before changing the global algorithm.
7. Compare changes against R4 and R5 outputs, keeping the model/runtime fixed.
8. Do not call a candidate better based only on paragraph count, median length, or a small set of hand-picked examples.
9. If the evidence is inconclusive, keep R4 and stop. Avoid an unbounded search for a theoretically perfect algorithm.

### Minimal decision checklist

- [ ] Does the proposed change solve the same identifiable problem in multiple transcripts?
- [ ] Does it preserve good boundaries as well as fix bad ones?
- [ ] Does it avoid splitting a statement from its example, explanation, or consequence?
- [ ] Does it avoid interrupting a continuous narrative?
- [ ] Are only paragraph boundaries changed?
- [ ] Has the same 93-transcript archive been used for comparison?
- [ ] Is there a documented reason to change from R4, rather than merely a desire to keep experimenting?

If the answer to the first two questions is not clearly yes, do not change the algorithm.
