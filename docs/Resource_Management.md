# Resource Management

Memora can automate Whisper self-tests on desktop and reduce the risk of iPhone interruptions by controlling when expensive work starts, bounding its working sets, and saving progress before each risky phase. Desktop automation can run continuously. The first iPhone implementation should support a saved suite with a restart boundary between configurations.

## Device observations

| Device | Reported behavior | Design implication |
|---|---|---|
| iPhone 12 Pro Max | Tiny passes, then Base passes. Starting Small next almost always crashes. Small passes when tested by itself after a restart. | Treat Small standalone and Small after Tiny → Base as distinct measurements. Insert a restart boundary before Small in that sequence at minimum. |
| Dell Alienware PC with NVIDIA GeForce RTX, 11 GB | An early Memora version ran automated self-tests successfully. | Restore continuous desktop suites using the current runner and validate on this PC. The earlier result gives a baseline for the workflow. |
| iPhone opening Dreams/2017 | The app failed early during audio-folder opening in Combine or Search, including after a phone restart. Opening transcripts first and then attaching audio later succeeded. | Instrument the picker handoff and preserve the transcripts-first path. An archive open can fail in a fresh session, so sequence cleanup alone cannot address both problems. |

The Tiny → Base → Small pattern points to a session-dependent trigger. Possible contributors include retained JS, WASM, or media allocations, delayed reclamation, other resident models, and a transient spike during Small's load or inference. Device traces have yet to establish which phase fails or whether iOS terminated WebKit for memory. Restart scope matters during validation. Record whether a test followed a page reload, a PWA close and reopen, or a phone restart. [Dreams/2017 investigation](iPhone_2017_Audio_Load_Investigation.md) · [Apple jetsam reports](https://developer.apple.com/documentation/xcode/identifying-high-memory-use-with-jetsam-event-reports)

## Automated Whisper suites

Use the current single-configuration runner under a suite controller. Settings offers **Run suite** with the ordered, currently supported configurations, progress and cancel. Keep **Run one test** available. Use the same fixture, validation, stage deadlines, typed failures and worker cleanup as manual tests. Pass an explicit suite execution mode through the journal and evidence layer so automatic attempts follow the existing failure and qualification contract. Preserve standalone passes and sequence outcomes in history. Apply any holds through the existing contract. [Self-test entry point](../js/whisperSelfTest.js) · [Lifecycle](../js/whisperTestLifecycle.js) · [Failure and qualification contract](Whisper_Execution_Failure_Contract.md)

| Mode | Execution | Interruption and recovery |
|---|---|---|
| **Continuous desktop** | Run one model at a time in selected order on the visible page. Await the final attempt write and worker cleanup before starting the next row. Start with the existing desktop configurations and test on the Alienware. | Pause on allocation/worker/device loss, uncertain cleanup, timeout, missing durable state or page loss. Show the failed or interrupted row and the pending rows. |
| **Restart between iPhone tests** | Start with one model per page session. Persist the result and next position, then offer **Restart before next test**. After reload, show the next configuration and let the user continue. If reload still leaves pressure, give the user a way to close and reopen the PWA without losing the saved suite. | Restore a paused suite after unexpected page loss. Let the user retry the interrupted configuration, skip it or end the suite. Record the original interruption and any later attempt independently. |
| **Validated iPhone sequences** | After on-device evidence, allow known combinations in one session. Tiny → Base is a candidate on the reported phone. Keep a restart before Small unless the current build and configuration demonstrate a reliable transition. | Pause on the first serious or ambiguous failure. A standalone Small pass qualifies only under the existing rules and supplies no evidence for the Tiny → Base → Small transition. |

A future foreground-only iPhone mode could automatically advance across *planned* reloads. It would persist and consume a one-use continuation tied to the suite, next position and expected navigation. A crash while an attempt is active would always restore a paused suite. Duplicate tabs, expired continuation, changed build or changed configuration context should require review before another model starts. Test planned reload against full PWA relaunch first, since reload does not guarantee a fresh WebKit process. An external desktop test harness could also drive the same entry point for regression runs. Hardware tests remain necessary for WebGPU and device-specific pressure.

### Persistence and ownership

- Save the ordered configuration IDs, suite mode, build and execution context, next position, run owner and linked attempt IDs. Keep per-model phases and outcomes in the existing attempt journal. Include each model's predecessor, page session and the gap since the prior attempt in the report.
- Reserve a position durably before model startup. Advance only after the terminal attempt record is durable. On startup, reconcile the saved suite position with the existing attempt ID so a crash after saving a result but before advancing cannot rerun a completed row. Pending rows still awaiting their turn remain unattempted.
- Allow one suite owner at a time. Where supported, use a browser lock for active ownership and a durable reservation to reconcile navigation and restarts. Pause when ownership is uncertain. Cancellation must release the worker, save the attempt state and leave remaining rows pending or stop the suite as selected.
- Keep one shared resource boundary for allocation-heavy phases on iPhone. Coordinate test loads, production transcription, semantic indexing and large archive preparation. Release idle production Whisper before decoding the fixture and add a release path for the idle semantic Search worker. Preserve active work and ensure cancellation settles before another operation starts. Model disposal and worker termination indicate cleanup progress. Actual memory reclamation depends on WebKit. [Whisper lifecycle](../js/whisperTestLifecycle.js) · [Semantic worker](../js/semantic.js)

## Large audio archives

1. **Locate the failing phase.** Extend the bounded runtime diagnostics with picker requested, selection delivered, identity inspection started and sampled progress, catalogue saved, transcript preparation complete and Search ready. Capture file count, aggregate and largest size, format counts, read count and bytes, elapsed time and active workers. Use ordinals and counts to protect file and transcript names. Recover unfinished operations as interrupted and offer the transcripts-first path. [Runtime diagnostics](../js/runtimeDiagnostics.js) · [Source flow](../js/app.js)
2. **Before picker handoff.** Files and WebKit can prepare the folder and its descendants before Memora receives the selection. If this is the failing phase, offer individual files or smaller batches that attach to an open transcript archive. Represent partial coverage and continue to verify IDs and check duplicates across attached batches. A size check after handoff can only govern Memora's subsequent work. [Picker](../js/storage.js)
3. **During identity inspection.** It already reads sequentially and uses bounded slices. If read counts or timings implicate provider overhead, test bounded read-ahead for nearby container reads or a progressive inventory with explicit pending and verified states. Preserve the fingerprint contract and ambiguity checks. Narrow catalogue queries and pruning to avoid materializing unrelated records in IndexedDB. [Audio catalogue](../js/audioFolderCache.js) · [Identity prefix contract](Recording_Identity_Prefix_Contract.md)
4. **During preparation and repeated opens.** Release stale Search index and playback references at the source lifecycle boundary. Delay optional recording details and wrappers for unselected children while preparing transcripts required by Combine and Search. If Search vectors dominate, prototype chunked storage and bounded reads and writes with a compatible import path for the existing embeddings archive. [Search reset](../js/searchUI.js) · [Search index](../js/search.js)

## Estimate work before allocating

Safari provides no dependable remaining-RAM budget for a PWA. Use operation estimates and prior outcomes to choose lower-cost paths. Record exact model configuration and cold or cached load, archive file counts and read patterns, Search vector count and dimensions, and audio duration, channels and decoded sample rate. Storage quota measures disk usage. Weight bytes, WASM linear-memory capacity, JS heap and GPU allocations each describe a different part of the workload. Fixed sleep intervals and successful worker disposal provide limited evidence for allowing the next model. [WebKit memory pressure discussion](https://bugs.webkit.org/show_bug.cgi?id=277848) · [WebKit storage policy](https://webkit.org/blog/14403/updates-to-storage-policy/) · [Whisper memory handoff](Memora_Whisper_Memory_Handoff.md)

Long-recording transcription deserves a separate limit from archive opening. The current whole-file decoder can hold compressed audio, decoded PCM and resampled PCM during one operation. One hour of Float32 stereo audio at 48 kHz takes about 1.29 GiB for the decoded samples alone. Evaluate direct target-rate decode and transferring owned PCM buffers where retry semantics permit. For bounded memory, prototype incremental demux and decode, then feed inference overlapping chunks with backpressure and verify timing and transcript quality at the boundaries. [Memora decoder](../js/audioProcessor.js) · [Web Audio](https://www.w3.org/TR/webaudio/#dom-baseaudiocontext-decodeaudiodata) · [WebCodecs](https://www.w3.org/TR/webcodecs/)

If resource-heavy operations still exceed practical PWA limits, a desktop companion can prepare indexes or transcribe locally. A native iOS companion could read samples incrementally through AVFoundation. A WKWebView wrapper can detect content-process termination and restore UI state, while heavy work inside the web content process remains subject to WebKit limits. An opt-in server is another option when uploading audio and relying on connectivity fit the workflow. [AVAssetReader](https://developer.apple.com/documentation/avfoundation/avassetreader) · [WKWebView termination callback](https://developer.apple.com/documentation/webkit/wknavigationdelegate/webviewwebcontentprocessdidterminate%28_%3A%29?changes=la_1&language=objc)

## Implementation and acceptance order

1. **Instrument and reduce overlap.** Add bounded archive phase markers, idle worker release and Search cleanup. Verify Combine and Search still receive their initial transcripts, audio identity and duplicate checks still hold, and stale playback URLs are released.
2. **Restore continuous desktop automation.** Run the selected suite on the Alienware and verify one worker at a time, ordered result persistence, cancellation, and pause on worker or persistence failure. Simulate interruption before and after saving a result, and check cross-tab ownership and duplicate prevention.
3. **Add saved iPhone suites with restart boundaries.** Verify Tiny, Base and Small can complete a suite across sessions with the queue and attempts intact. Compare Small alone, Small after Tiny and Base with a planned reload, and Small after PWA close and reopen if needed. Use the already reported continuous failure as the initial comparison and avoid repeated crash runs. Capture phase, device, iOS and build, cold or cached load, prior Search activity, and available Apple diagnostics. Consider continuous transitions only for combinations that show repeatable stability.
4. **Follow the evidence.** If archive failure occurs before picker delivery, prioritize limited selection. If it occurs during inspection, measure provider reads. If it occurs later, profile indexing and metadata work. Use Safari Web Inspector and available jetsam reports alongside uninstrumented runs on the affected phone. [Web Inspector Memory timeline](https://webkit.org/web-inspector/timelines-tab/) · [Apple jetsam reports](https://developer.apple.com/documentation/xcode/identifying-high-memory-use-with-jetsam-event-reports)
